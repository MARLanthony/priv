================================================================================
RELATIONSHIPS
--------------------------------------------------------------------------------
  users(1) ── clients(1)                a client login owns one client file
  users(1) ── cases(N)                  assigned_lawyer_id (the lead attorney)
  users(1) ── appointments(N)           whose diary the booking sits in
  users(1) ── availability(7)           the weekly grid
  users(1) ── notifications(N)          the inbox
  users(1) ── notification_settings(1)  preferences
  users(N) ── permissions(N)            through role_permissions, by role
  clients(1) ── cases(N)                matters, cascade
  clients(1) ── consultations(N)        intake, cascade
  clients(1) ── appointments(N)         bookings, cascade
  clients(1) ── documents(N)            uploads, cascade
  cases(1) ── documents(N)              case_id, ON DELETE SET NULL
  consultations(1) ── appointments(N)   consultation_id, ON DELETE SET NULL
  documents(1) ── nlp_results(1)        newest analysis per document wins
  legal_services(1) ── consultations(N) service_id, ON DELETE SET NULL

================================================================================
KEY CONSTRAINTS
--------------------------------------------------------------------------------
  users.email                     UNIQUE (citext)      one account per address
  clients.user_id                 UNIQUE               one file per login
  cases.case_number               UNIQUE               JF-2026-1001 …
  availability (lawyer_id, day)   UNIQUE               one row per weekday
  role_permissions (role, perm)   UNIQUE               one grant per pair
  appointments_no_overlap         EXCLUDE USING gist   no double-booking
  appointments_time_order         CHECK end > start
  consultations.concern           CHECK length >= 20
  users.role / statuses / kinds   CHECK (in list)      controlled vocabularies
